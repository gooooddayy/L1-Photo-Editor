## 一、功能清单（全部已实现并 E2E 验证）

### 基础编辑
| 功能 | 实现要点 |
|---|---|
| 导入 | file input + 拖拽 + Ctrl+V 粘贴；大小不限 |
| 比例裁剪 | 11 chips：原图/自由/1:1/16:9/9:16/4:3/3:4/16:10/10:16/3:2/2:3；锚点式拖拽（对边/对角固定，等比盒钳位）；默认「原图」比例 |
| 旋转 | 逆时针 90° 循环；`translate(0, out.height)`（非 out.width，方形图测不出此 bug） |
| 镜像 | 水平翻转 |
| 马赛克 | 圆形区域像素化，笔刷沿线插值补采样（快速拖不断线） |
| 文字 | 大小/颜色(默认#ff0000)/加粗，可拖动，合并到图；真实字号按 `size × base.width/800` 随图缩放 |
| 撤销 | 快照历史，HIST_MAX 按内存自适应 5–15 |
| 导出 | JPG/JPEG/PNG/WEBP/BMP/ICO(+AVIF 探测)；BMP 手写 24-bit 编码器，ICO=PNG 内嵌 256 钳位；37 个预设尺寸分组下拉 + 自定义 W/H + 锁比例 |

### 裁剪等比算法（129,360 组合测例 0 失败）
角/左右边拖拽：锚点=对边/对角；`maxH=锚点到边界`、`maxW=min(水平余量, maxH×CR)`，宽度钳位在等比盒内，高=宽/CR，防越界与塌缩。拖新框：`w=max(w0, h0×CR)` 后整体钳回图内。

### 导出尺寸联动（用户定义语义）
- 锁定比例 = **勾选时刻的当前 W/H 数值比**（`lockAr`），非原图比例、非输出比例；重勾/选预设时重设 lockAr
- 默认勾选；尺寸下拉 ↔ W/H 双向实时联动，匹配不到预设显示「自定义」；默认「原始尺寸」
- 估算 = 与导出**完全相同的绘制路径**（同 contain-fit、同 imageSmoothingQuality="high"）后真实 toBlob 编码 → 预估≈实际（同一浏览器编码器确定性）
- "不超过 X MB"：doExport 最多 24 轮降质/降尺寸循环压到限内

### AI 抠图（SILUETA）与移除（MI-GAN）
见第三节模型决策。管线：
- **抠图**：320×320 缩放 → ImageNet 归一化 → f32 [1,3,320,320] → outputNames[0] → **min-max 归一化** alpha → 双线性放大到全图 → 乘 alpha
- **移除**：maskBBox + 35% pad 取 ROI → 长边 ≤512 缩放 → image uint8 CHW [1,3,H,W] + mask uint8 [1,1,H,W]（**0=待修补，255=保留**）→ 输出贴回 ROI
- 引擎：ORT 1.16.3（内联 glue，无动态 .mjs，file:// 可用）；`ort.env.wasm.numThreads=1`（file:// 非 COI）
- 离线关键：wasm 二进制 base64 → **Blob URL** → `ort.env.wasm.wasmPaths = {文件名: blobUrl}`（对象形式映射）
- 模型三级加载：本地 b64 `<script>` → IndexedDB（key `_v2`）→ 在线链（hf-mirror 优先，支持 CORS+Range）
- 报错分级：`aiErr()` 区分「ort 文件夹缺失 / 本地 wasm 缺失+断网 / no available backend 转译」，且检测 127.0.0.1 预览环境提示「双击本地文件打开」

### UI（v11 定稿）
浅灰白底 + 绿色主题 + SVG 图标；毛玻璃面板；功能面板**固定顶部布局流内**，展开时 `fitView()` 重算 → 图片显示自动缩小让位（**真实分辨率/导出/AI 全部不受影响**）；resize 时同步重算。

## 二、架构决策

1. **单文件 HTML + 两个资源文件夹**：HTML 内联全部逻辑；`ort/ort.min.js`(557KB) + `ort/ort-wasm.b64.js`(27.7MB，含 simd 与 simd-threaded 两个变体的 base64)；`models/*.b64.js`（模型 base64，按 key 懒加载）。
2. **ORT 版本选 1.16.3 而非 1.19.2**：1.19 的 glue 是外部 .mjs 动态 import，file:// 下无法离线；1.16.3 内联 glue 可用。
3. **wasm 注入用 wasmPaths 对象映射而非 wasmBinary**：1.16.3 忽略 wasmBinary（1.17+ mjs 架构才支持）；min 代码确认 `wasmPaths` 支持对象形式（filename→URL）。
4. **file:// 离线三板斧**：`<script src>` 可读本地文件（fetch 不行）→ 大模型走 base64 JS；wasm 走 Blob URL；IndexedDB 做联网下载后的缓存。
5. **验证体系**：playwright（`chromium.launch({channel:"msedge"})`，本机只有 Edge）+ `page.route` 阻断所有非 file:// 请求做**断网 E2E**；像素级断言（透明占比、扫描线连续性、面板/画布 rect 对比）；onnxruntime-node 做**语义对照实验**（浏览器侧疑难时用 node 端最小复现定语义）。

## 三、模型选型结论（需求=通用大部分场景，纯本地 CPU）

| 模型 | 体积 | 结论 |
|---|---|---|
| **SILUETA（抠图，现用）** | 42MB | u2net 作者官方蒸馏，精度≈完整版 95%，与 u2netp 完全同构（input.1 [1,3,320,320] f32 → 7 输出） |
| u2net 完整版 | 168MB | 边缘更细但体积×4、CPU 慢 2-3 倍，不划算 |
| **MI-GAN pipeline_v2（移除，现用）** | 28MB | 浏览器端移除事实标准（inpaint-web 同款），512 训练 |
| LaMa | 200MB+ | 质量上限高，但 FFT 算子 wasm 不友好 + 慢 10 倍 |
| RMBG-2.0/BiRefNet | 930MB+ | 不可行 |
| MODNet | 25MB | 人像特化，可作将来「人像模式」按需选项 |

速度优化留白：部署 https 后可开 WebGPU EP + COI 多线程（快 3-10 倍，体积不变）。

## 四、踩坑记录（按代价排序）

### 🔴 致命级
1. **MI-GAN mask 语义反了**：约定 **0=待修补(hole)、255=保留**。涂白区设 255 → 模型把涂抹区当保留、把周围全图当洞重绘 → 表现为"消不掉+全图乱"。修复：`alpha>40 ? 0 : 255`。对照实验：绿底白方块，hole=0 时输出≈背景色 ✓。inpaint-web 源码佐证：`(灰度!==255)*255`。
2. **Chromium data: URI 2MB 上限**：内联 wasm 的 data URI 超限 → `Failed to fetch`。Blob URL 无限制。
3. **ORT 1.16.3 忽略 wasmBinary**：必须走 wasmPaths；且 **file:// 下有 SharedArrayBuffer → ORT 选 simd-threaded 变体** → 两个 wasm 变体都要提供。
4. **裁剪「原图」chip 只加了高亮没设内部值**：`cropRatio` 仍是 0（自由）。UI 状态与内部状态必须同步赋值。字符串 `"orig"` 直乘产生 NaN 的隐患（拖新框/fitRatioRect 两处）→ 统一走 `ratioVal()`。

### 🟡 坑级
5. **旋转非方形图显示残缺**：CCW90 应 `translate(0, out.height)`；方形测试图测不出，测试图别全用正方形。
6. **模型文件名与代码 key 不一致**：`B64_KEY` 按 key 拼 `models/<key>.b64.js`，文件叫 `migan_pipeline_v2.b64.js` → 404 → 静默掉在线链。命名约定优先于映射表。
7. **IndexedDB 缓存旧模型**：换模型必须升版本号（`_v1`→`_v2`），否则老用户命中旧缓存。
8. **256px 采样外推估体积**：PNG 压缩非线性，噪声图大尺寸外推偏差数倍 → 改真实全尺寸编码。
9. **涂抹/马赛克快速拖断线**：`if(dist<step) return` 会丢段 → 沿线插值补圆。
10. **面板推挤/遮挡布局**：三轮迭代教训——布局流推挤 → absolute 悬浮遮图 → **最终：布局流 + fitView 自适应**（需求先问清"推挤还是遮挡哪个可接受"）。
11. **ctx 面板 display:flex 在 .show 丢了**：改 CSS 时把 show 态的 display 覆盖删掉 → 面板打不开。改基础规则时检查状态类。
12. **Edit 工具吞行**：old_string 含下一选择器开头时 new_string 忘带回 → CSS 结构损坏。大段 DOM/CSS 移动用 node 脚本正则提取回插更稳。

### 🔵 测试方法论坑
13. **E2E 只验 toast 不验像素**：AI 功能"跑完不报错"≠效果正确。视觉功能必须导出像素做断言或目视。
14. **测试脚本 patch 用正则替换不验证**：replace 没匹配也打"PATCHED" → 两轮假结论。patch 后必须 `grep -c` 验证。
15. **测试涂抹覆盖不足误判为模型问题**：40px 涂抹带盖不住 90px 文字，露出笔画被模型延续回来。测试输入要和真实使用同量级。
16. **合成图太理想**：纯色图测不出边缘/纹理问题，测试图要有渐变+噪声+细节。
17. **playwright-cli 与本机 playwright alpha 版不兼容**（exports 不暴露子路径）→ 直接 require playwright 库写独立驱动脚本 + `channel:"msedge"`。
18. **GitHub release 下载慢且无 CORS**（浏览器不可用）：hf-mirror 快 4 倍且支持 CORS+Range，模型在线链一律 hf-mirror 优先。
19. **自动滚动/等长的 sleep 不可靠**：AI 推理耗时随图变化，等待要留足余量（移除 30s）。

### 在线模型下载链路（实测调优三轮）
| 链序 | 源 | 实测 |
|---|---|---|
| 1 | 同源 `models/*.onnx`（Pages） | 实时随仓库更新；慢（本网络 ~80KB/s 且易断）但可用 |
| 2 | **jsDelivr 分片**：onnx 切 <20MB 分片（u2netp×3 + migan×2），逐片 fetch 拼接 | 快且稳（CDN），完整在线抠图 79s 成功 ✓ |
| 3/4 | hf-mirror / huggingface | ⚠️ 本网络浏览器 fetch 被断（TLS 特征阻断，curl 可通但浏览器不行），仅作最后保底 |

- **jsDelivr 对 gh 源单文件限 20MB** → 大模型必须切片；`@main` 分支引用有 12h 缓存 → 模型文件更新后备链最长延迟 12h（同源始终实时）
- **教训：hf-mirror/ghproxy 类镜像不可作为浏览器 fetch 依赖**（CORS 重定向丢失/服务随时失效）；ghproxy 类第三方加速不写入代码（违背长期可用）
- getModel 支持 urls 数组项为「分片组」：`Array.isArray(url)` 时逐片下载拼接，进度条按累计字节
- fetchBuf 双超时：连接 30s、读流单次 45s 无进展即断

### file:// 与 https 双路径分流（重要）
- `location.protocol === "file:"` → 模型走 b64 `<script>`、wasm 走 Blob URL 注入（离线）
- https/http → 模型直接 fetch 同源 onnx（42MB，比 56MB 的 b64 小且有进度条）、wasm 走 jsDelivr npm 的原生 wasm（~10MB，比 27.7MB b64 快数倍）
- 两路径已分别实测：离线双功能 ✓、在线抠图 79s ✓

## 七、v13/v14 手机大图内存优化（2026-10-19 补）

### 问题现象
手机（12-48MP 拍照图）点抠图后卡死在"正在抠图"。根因：模型推理本身只占几百 MB，真正爆内存的是**推理结果回贴 base 的那一步**：

- 全尺寸 `getImageData()` ×2（base 一份 + mask 一份）+ `putImageData()` ×1
- 12MP 图：每份 ImageData ≈ 48MB，三份往返（JS 堆 + native 双计）瞬间 100-400MB → 低端机 OOM / 页面被杀

### 修复 1：destination-in 合成替代像素循环（v13）
数学依据：base 不透明（alpha=255）时，`destination-in` 的结果 `alpha_out = base_alpha × mask_alpha / 255 = mask_alpha`，与手写逐像素乘法**完全等价**，且零像素循环、GPU 合成器内完成：

```js
sc.putImageData(sd, 0, 0);          // mask 写入小画布
bctx.save();
bctx.globalCompositeOperation = "destination-in";
bctx.drawImage(mSmall, 0, 0, base.width, base.height);  // alpha 相乘
bctx.restore();
```

实测 12MP 视口抠图 7s 完成；像素级断言：抠图区中心 alpha=255、四角=0。

### 修复 2：maskBBox 增量缓存（v14）
移除功能原版在每次点"移除"时全图扫描 alpha>40 求涂抹区外接框 → 12MP 又是 48MB/次。改为：

- 涂抹时 **O(1) 增量扩展缓存**：每个插值圆与旧 bbox 取并集（两端圆 ±r 已覆盖全部插值圆）
- 失效点必须全部置空 `maskBB = null`：`resetMask()`、undo、旋转/镜像 transform、裁剪——这四处都是 maskC 画布重建的入口，漏一处就会用过期 bbox 算错结果

### 新增踩坑记录（承接第四章编号）
20. **canvas alpha 乘法优先用合成模式（destination-in），不要手写大像素循环**——数学等价时合成在浏览器内部完成，内存与耗时差一个数量级；大图尤其致命。
21. **保守超集断言用"包含+容差"而非严格相等**——几何圆外接框 ⊇ 抗锯齿 alpha>40 区域是预期行为，严格相等断言必失败。
22. **git push 走系统代理 502/schannel 失败** → `git -c http.proxy= -c https.proxy= push` 直连解决。

## 八、手机抠图永久卡死——渲染进程 OOM 崩溃与双模型方案（2026-10-19 补，v14.2）

### 现象与排查过程
手机上抠图永远停在「正在抠图」，移除功能正常。桌面模拟无法复现（桌面内存充裕）。最终靠 **adb 取证**定位（用户手机连电脑，只读操作）：

```bash
adb logcat -d | grep -iE "lowmemorykiller|chromium.*Renderer.*crash|Zygote.*exited due to signal"
```

实锤日志（崩溃时刻 18:29:28）：
```
lowmemorykiller: device memory ... free 54115          ← 系统可用内存仅 54MB，连环告警
Zygote: Process 16722 exited due to signal 31 (Bad system call)
chromium: [ERROR:aw_browser_terminator.cc(156)] Renderer process (16722) crash detected (code 11)
```

### 死因链（关键认知）
1. 界面停在「正在抠图」= 模型下载✓、会话创建✓，卡在 `sess.run()` 推理内部
2. SILUETA 42MB + u2net 架构在 320×320 下的激活内存（数百 MB 级），叠加系统瞬时低内存 → **WebView 渲染子进程被压崩**
3. **渲染进程一死，JS 层完全无感知**：事件循环消失 → `run()` 的 promise 永不 settle、catch 永不触发、toast 永不弹 → 界面永久卡死。这是 ORT-web「静默挂死」的真实机理
4. 移除用 MI-GAN 28MB + 小区域裁剪输入，内存占用低一截，同一场风暴里活下来了
5. 崩溃时机 = 大分配 + 瞬时低内存同时发生（设备 11GB 内存也会中招，不能依赖"用户先清后台"）

### 修复方案（双模型分设备，以 PC 为准）
```
IS_TOUCH = matchMedia("(pointer:coarse)").matches && (/Android|iPhone|iPad|Mobile/i.test(ua) || maxTouchPoints > 1)
```
- **电脑**：SILUETA 42MB，一切不变（双条件判定保证鼠标/触控板设备永不误入手机分支）
- **手机**：u2netp 4.4MB（rembg 官方版，input.1 [1,3,320,320] 固定 → outputNames[0] [1,1,320,320]，管线代码零改动）+ `enableCpuMemArena:false` + proxy off + 会话创建后 `buf = null` 释放 JS 侧引用
- u2netp_s 模型入库：`models/u2netp_s.onnx`（4.4MB，jsDelivr 单文件 <20MB 无需分片）+ `u2netp_s.b64.js`（file:// 离线兜底）

### 方案演进中的关键发现
- 原计划"手机端把推理分辨率 320→224 省内存（激活内存 -51%）"——**E2E 实测 SILUETA 输入固定 320×320**，喂 224 直接报 `Got: 224 Expected: 320` → 方案作废。u2net 系 onnx 输入尺寸固定，改分辨率前必须先验证模型 dims
- 手机端不开 proxy worker（回退到与"移除"完全相同的已验证路径），排除 sandbox 线程变量
- 历史教训（v14.1→v14.2）：为排障加的常驻诊断 UI（屏幕日志条/计时器/✕取消）被要求全部拆除——主界面零干扰优先于排障便利，**诊断 UI 先问再加**

### 新增踩坑记录（承接第四章编号）
23. **手机 AI "永久卡死"优先怀疑渲染进程被杀**，不是 JS 死循环——进程死亡时 promise 永不 settle、无任何报错，JS 层 try/catch 完全无用。取证靠 adb logcat，别在 JS 里干找。
24. **u2net 系 onnx 输入尺寸固定 320×320**，想降分辨率省内存前先用 onnxruntime 验证 dims，别默认全卷积可变输入。
25. **诊断/日志 UI 不要常驻主界面**，要加先跟用户确认；排障结束后必须拆干净（grep 零残留）。
26. **E2E 像素断言用已知特征点**（测试图里画白圆盘采样其中心），纯渐变背景的中心 alpha 中等值是正常输出，拿它当断言点会误判 FAIL。
27. **adb 取证三板斧**：`lowmemorykiller`（内存压力）、`chromium.*Renderer.*crash`（渲染进程崩溃）、`Zygote.*exited due to signal`（死因信号）；WebView 套壳浏览器（如 com.mmbox.xbrowser）无 CDP 调试口，logcat 是唯一窗口。

### APK 新增踩坑（承接第四章编号）

28. **OnnxTensor 不写 OnnxJavaType 默认 INT8**：`OnnxTensor.createTensor(env, ByteBuffer, shape, OnnxJavaType.UINT8)` 必须显式指定 UINT8——Java `byte[]` 是有符号的，漏写会被 ORT 以 `tensor(int8) vs uint8` 拒绝，表现为"移除失败：推理失败"。
29. **`Canvas.drawBitmap(bmp, left, top, paint)` 是 1:1 原尺寸绘制，不缩放**：非原始比例导出"只显示左上角"的根因。必须改用 `(bmp, null, dstRect, paint)` 或 Matrix 重载。原始尺寸导出恰好正确掩盖了这个 v1.0 起潜伏的 bug。
30. **Android PathParser 语法严格**：M/L 后坐标必须成偶数个（polyline 转换要两两配对）；SVG 命令参数个数表 M/mL/lTt:2、HhVv:1、Cc:6、SsQq:4、Aa:7。非法 pathData 直接启动闪退。
31. **configChanges 必须全量声明**：`orientation|screenSize|screenLayout|smallestScreenSize|keyboardHidden|density|fontScale|uiMode`——配置变化不重建 Activity，`onConfigurationChanged` 里重建 UI（复用 EditorView 实例）；重建前要 `exitModes` + dismiss 已开对话框（防错位）+ 恢复进度浮层。
32. **估算缓存一致性闸**：estGen 内容代数（pushHistory 递增）+ 参数 key，同参数导出直接复用估算编码结果（二次导出 395ms）。
33. **release 构建链**：JDK11 + gradle 7.3.3 `assembleRelease` → `zipalign -p 4` → `apksigner`（v2+v3，minSdk 24 无需 v1）；⚠️ `aapt.exe` 打不开中文文件名 APK（GBK Illegal byte sequence），核验前先 cp 成 ASCII 名。
34. **playwright E2E 三坑**：① 页面顶层 `let` 不挂 `window`，`waitForFunction('window.x')` 永远 undefined，要用裸标识符；② `waitForFunction` 第 2 参是 arg 不是 options；③ 跨上下文轮询不稳定 → 统一改页内 `evaluate` 轮询；fire-and-forget 的 `toBlob` 不可靠，要 await。
35. **iOS canvas 16.7M 像素面积上限**：超 24MP 导入需 `Math.sqrt(24/mpRaw)` 采样钳位，否则 iOS Safari 导出白屏。

### 新增踩坑记录（2026-10-21，承接第四章编号）

36. **ort wasm 引擎初始化是单例，proxy 策略必须全程一致**：同一页面里先跑 `proxy=true`（抠图，worker 内初始化 wasm）再切 `proxy=false`（移除，主线程），backend 的 init 已被 proxy 路径消费、主线程 wasm 永远未初始化 → `getInstance()` 抛 `"WebAssembly is not initialized yet."`。老 bug，仅「PC 在线版 + 先抠图后移除」触发（file:// 与移动端 proxy 恒 false 不受影响）。修复 = 移除与抠图用同一条 proxy 判定。E2E 三组对照：抠图✅ / 抠图→移除❌ / 刷新后直接移除✅。
37. **导出循环条件加 `&& !blob` 会杀死 MB 限制压缩**：blob 每轮必赋值 → `!blob` 第 2 轮即 false → 降质量/缩尺寸只跑 1 轮就退出，超限直接报错（JPG 624ms 即报错是实锤特征）。估算缓存的"跳过循环"必须用 `if(!blob) for(...)` 整段包住。⚠️ 改导出循环后必须补 `lim<Infinity` 断言——当时只测了不限路径导致回归漏网。
