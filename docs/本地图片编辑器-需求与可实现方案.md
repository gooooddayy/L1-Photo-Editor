| "image-matting / background-removal-js / light-converter / ComfyUI-RMBG" | 你找的四个参考 | 第 5 章逐一研判 | — | light-converter 为主参考，其余只借鉴 |

| "图片格式支持jpg、jpeg、png等常见格式" | 导入格式范围 | F1 导入 | webp/bmp 算不算"常见"？ | jpg/jpeg/png 必做，webp 顺手支持 |
| "大小限制：小于等于 10MB" | 文件体积限制 | F1 / F10 | 限制输入还是输出？ | 输入 ≤10MB 硬限制；输出加"≤10MB"开关 |

四条典型使用路径（决定 UI 优先级）：

1. **改尺寸**：导入 → 选 1500×1500 → 导出。要求这条路三步内完成。
2. **社媒配图**：裁 16:9 → 文字 → 给路人打码 → 导出。
3. **透明底素材**：抠图 → 换底色 → 导出 PNG。
4. **去路人/杂物**：涂抹 → 移除 → 裁剪 → 导出。

v1 明确不做：调色滤镜、图层混合、RAW/HEIC 解码、GIF/视频、云端与账号、生成式重绘、移动端。

## 5. 参考项目研判（六个 + 两个补充）

### 5.1 你给的六个

| 项目 | 一句话定位 | 技术事实 | 对本项目的作用 |
|---|---|---|---|
| rembg | Python 抠图库/CLI/HTTP 服务 | Python 3.11–3.13 + onnxruntime；默认 bria-rmbg 约 1.02GB；代码 MIT，默认模型非商用；`rembg s` 可起 HTTP | 效果标尺；可选后端；其 alpha matting / 颜色去污思路借鉴 |
| IOPaint | 完整的 AI 修补 Web 应用 | FastAPI + PyTorch + Vue；`iopaint start --model=lama --device=cpu`；`POST /api/v1/inpaint`（base64 image+mask → PNG）；Apache-2.0 | API 形态与 ROI+mask 流程参考；可选高质量后端；不直接嵌入 |
| image-matting | Windows 桌面抠图工具 | pywebview + FastAPI(11111) + Vue；RMBG-1.4；**CC BY-NC 4.0 非商用** | 产品功能清单参考（批量/证件照/底色切换）；代码与模型均不复用 |
| background-removal-js | 浏览器抠图 npm 库 | onnxruntime-web；RMBG-1.4 量化 44/88MB；可自托管模型；**AGPL-3.0 + 模型非商用** | 证明"44MB 模型浏览器可跑"；缓存与 Worker 设计借鉴；不直接依赖 |
| light-converter | 纯浏览器批量去背景站 | Astro+Svelte+ORT-web；WebGPU 走 BiRefNet-tiny fp16（MIT），WASM 回退 IS-Net int8（Apache-2.0）；guided filter、连通域清理、IndexedDB/Cache Storage；**MIT** | **主参考**。双后端策略、边缘细化、笔刷修边、本地缓存整套范式 |
| ComfyUI-RMBG | ComfyUI 抠图节点包 | torch/ORT，建议 GPU；模型矩阵最全（RMBG-2.0/BiRefNet 全家/SAM 系/Lucida/SDMatte）；GPL-3.0 | 仅作模型字典：BiRefNet 系擅长毛发与半透明 |

### 5.2 补充的两个关键参考

- **inpaint-web**（lxfater，MIT）：纯浏览器 MI-GAN 涂抹修复 + 超分。证明 28MB 的小模型在浏览器里接近实时，"涂抹→执行→对比"交互可直接照抄。
- **inpainting.app 工程笔记**：作者公开的踩坑实录，直接决定技术细节——
  - MI-GAN 约 28MB，WASM 单块 512×512 约 0.6s；LaMa fp32 约 198–208MB，同尺寸约 4.3s；
  - **LaMa 在 WebGPU 会静默输出错误（填出大面积白色），必须锁 WASM**；
  - BiRefNet 在部分设备上超出 WASM 4GB 内存或 WebGPU buffer 上限，低配必须回退 IS-Net；
  - 大模型写 IndexedDB 必须分块，否则可能写崩标签页。

### 5.3 研判结论

- **能直接当引擎的**：onnxruntime-web + IS-Net / MI-GAN / LaMa（许可干净、体积可控、CPU 可跑）。
- **只借思路的**：imgly（缓存）、IOPaint（API 与插件分层）、image-matting（功能组织）、ComfyUI-RMBG（模型视野）。
- **主参考代码**：light-converter（MIT，可合法借鉴至接近照抄的程度）。

## 6. 技术选型与架构

### 6.1 三条路线（结论：A 起步，接口按 C 设计）

| 维度 | A 纯前端 | B Python 后端 | C 混合 |
|---|---|---|---|
| 安装体积 | 90–350MB（按档位） | 3–5GB | A + 可选 B |
| 启动 | 双击 1–2s | 10–30s | 同 A |
| 抠图/移除质量 | 中上 | 高 | 按需 |
| 你的机器速度 | 2–8s/次 | CPU 更慢 | — |
| 离线与隐私 | 完全 | 首次要下模型 | 完全 |
| 维护成本 | 低 | 高 | 中 |

选 A 的核心理由：你没有 N 卡，Python 在 CPU 上不占优；而 A 解压即用、完全离线、隐私最好、和你现有工具栈一致。做法上定义 `SegmentProvider` / `InpaintProvider` 两个接口，将来想上 rembg/IOPaint 只加一个 HTTP 实现类，UI 零改动。

### 6.2 分层架构

```
┌──────────────────────────────────────────────────────────┐
│ UI 层：工具栏 / 画布 / 属性面板 / 状态栏 / 快捷键           │
├──────────────────────────────────────────────────────────┤
│ 编辑内核：Document · Command · History · Mode 状态机       │
├────────────────────────────┬─────────────────────────────┤
│ 渲染管线（Canvas 2D）       │ AI 调度（单 Worker 串行）     │
│ 预览路径 / 导出路径          │ SegmentProvider · InpaintProvider│
│ 坐标变换 · 裁剪 · 合成       │ ORT-web（WASM 主 / WebGPU 实验）│
├────────────────────────────┴─────────────────────────────┤
│ 资源层：models/*.onnx · ort-wasm · 字体栈 · IndexedDB 草稿 │
├──────────────────────────────────────────────────────────┤
│ 本地壳：静态服务(127.0.0.1+COOP/COEP+CSP) · 启动器/EXE     │
└──────────────────────────────────────────────────────────┘
```

### 6.3 技术栈决定

- **零框架**：原生 HTML/CSS/ES Module，不用 React/Vue，不用打包器。理由：可调试性好、你看得懂改得动、体积小、没有供应链风险。
- **Canvas 2D** 做全部编辑渲染；AI 放 Web Worker。
- **ORT-web 固定版本**（建议 1.20.x），wasm 文件随包本地化，不走 CDN。

## 7. 系统核心设计

### 7.1 数据模型

```ts
type Doc = {
  source: ImageBitmap;              // 原图，只读
  meta: { name; mime; bytes; width; height; hasAlpha };
  base: ImageBitmap;                // 当前底图（旋转/镜像/抠图/移除/应用裁剪后的结果）
  baseVersion: number;              // 缓存失效依据
  annotations: {
    mosaics: MosaicStroke[];        // 马赛克笔画
    texts: TextItem[];              // 文字对象
  };
  crop: { x; y; w; h; aspect: number | null };
  view: { scale; tx; ty };
  mode: 'idle' | 'crop' | 'mosaic' | 'text' | 'removeMask' | 'processing';
};
```

**铁律：所有几何参数（笔刷直径、马赛克块、字号、坐标）一律以"底图像素"为单位存储。** 预览时乘 `view.scale`，导出时乘 1。预览永远不写回参数。

### 7.2 双分辨率渲染管线

```
预览：base --×scale--> 屏幕画布（底图 → 马赛克层 → 文字 → 裁剪遮罩UI）
导出：base --crop取景--> 临时画布（马赛克 → 文字）--一次重采样--> 目标尺寸 --toBlob--> 文件
```

三条纪律：预览不写参数；导出只做一次重采样（裁剪+缩放合并成一次 `drawImage`）；文字导出按目标分辨率重新排版，绝不放大预览位图。

### 7.3 模式状态机与快捷键

| 模式 | 进入 | 行为 | 退出 |
|---|---|---|---|
| idle | 默认 | 平移/缩放画布 | 点工具 |
| crop | C 键或按钮 | 显示裁剪框与 8 手柄 | 应用（生成历史点）/ Esc 取消 |
| mosaic | M 键 | 笔刷涂抹 | 切换工具 |
| text | T 键 | 点击处创建文字 | 切换工具 |
| removeMask | E 键 | 涂抹移除区域 | 执行 / 清除 |
| processing | AI 执行中 | 全工具锁定，显示进度/取消 | 完成/取消/超时 |

快捷键：`Ctrl+Z / Ctrl+Y` 撤销重做、`Ctrl+S` 导出、`Delete` 删除选中文字、`Esc` 取消当前操作、空格+拖动平移、滚轮缩放（0.05–8 倍，以鼠标为锚点）。

### 7.4 历史与内存

| 操作类型 | 记录方式 | 上限 |
|---|---|---|
| 改裁剪框 / 文字属性 / 马赛克增删 | JSON 快照（KB 级） | 30 步 |
| 旋转 / 镜像 | 逆操作（零位图成本） | 同上 |
| 抠图 / 移除 / 应用裁剪 | 保留旧底图引用（破坏性提交点） | 3 个版本，更早转 WebP Blob |

内存预算（估算）：

| 项目 | 12MP | 24MP |
|---|---|---|
| base RGBA | 48MB | 96MB |
| 预览画布 | 8MB | 8MB |
| 马赛克层 | 12MB | 24MB |
| AI session | 300–600MB | 300–600MB |
| 3 个底图版本 | 144MB | 288MB |
| 峰值 | 约 0.6–1GB | 约 1–1.5GB |

16GB 够用，前提是守住 24MP 上限并及时 `ImageBitmap.close()`。

## 8. 逐功能实现规格

每项按"交互 / 算法 / 边界与失败 / 验收"四段写。

### 8.1 F1 导入

- **交互**：拖入画布、点击按钮、`Ctrl+V` 粘贴；成功后自动适配视图。
- **算法**：`createImageBitmap(file, { imageOrientation: 'from-image' })` 解码（EXIF 自动摆正）；校验 MIME 与体积；像素超限（长边 >6000 或面积 >24MP）等比降采样并提示。
- **边界与失败**：>10MB 拒绝并显示实际大小；0 字节/损坏文件给可读错误；GIF 取第一帧并提示转静态。
- **验收**：EXIF 竖拍照片方向正确；10MB 边界文件可导入；错误提示中文可读。

### 8.2 F2 比例裁剪

- **交互**：预设比例条（原始/1:1/16:9/9:16/4:3/3:4/16:10/10:16/3:2/2:3）；8 向手柄 + 框内拖动 + 框外新建；滚轮缩放画布；"应用"后才生效。
- **算法**：
  - 预设点击：在当前裁剪框中心放置该比例的最大内接矩形（clamp 到边界）。
  - 锁比例拖拽：`w = clamp(rawW, 32, maxW); h = w/r; if (h > maxH) { h = maxH; w = h*r; }`，按锚点回推 x/y。
  - 切换比例：以现有框中心为锚点重建，避免跳到角落。
  - 旋转后矩形映射（逆时针 90°，W 为旋转前宽）：`(x,y,w,h) → (y, W-x-w, h, w)`；水平镜像：`x → W-x-w`。两公式必须有四角度单元测试。
- **边界与失败**：最小 32px 防零宽；手柄拖出边界时 clamp；旋转/镜像后裁剪框同步变换并 clamp。
- **验收**：输出比例与所选误差 ≤1px；旋转 4 次 + 裁剪来回，像素 diff = 0。

### 8.3 F3 旋转

- **交互**：一个按钮，每点一次逆时针 90°；状态栏显示当前角度。
- **算法**：离屏画布整数像素旋转（`translate(0,W); rotate(-π/2)`），**不插值**，因此无损；同步变换裁剪框、马赛克、文字坐标；`view` 重新适配。
- **边界与失败**：旋转后宽高互换，画布重新 fit；文字对象角度同步 +90°。
- **验收**：连转 4 次逐像素 diff = 0（自动化断言）。

### 8.4 F4 镜像

- **交互**：水平、垂直两个按钮。
- **算法**：离屏画布 `scale(-1,1)` 翻转，无损；坐标同步变换。
- **验收**：镜像两次 diff = 0；与旋转组合仍无损。

### 8.5 F5 马赛克

- **交互**：笔刷涂抹；可调笔刷大小（1–200px）、块大小（4–64px）、边缘硬度；可撤销单笔。
- **算法**：底图按 `block` 降采样再关平滑放大得到像素化图层（按 `baseVersion` 缓存）；笔刷轨迹画成遮罩；像素化图层经遮罩合成回画布。预览层用 `block × view.scale` 重建，保证与导出视觉一致。
- **顺序语义**：马赛克永远在文字之下（先打码后写字不会互相破坏）。
- **边界与失败**：超小图（<200px）限制最小块；笔画点按 2px 间距采样防爆炸。
- **验收**：同一参数下预览与 1500px 导出的马赛克颗粒肉眼一致。

### 8.6 F6 文字

- **交互**：T 键 + 点击画布创建；右侧面板编辑内容/字号/颜色/描边/透明度/旋转；拖动移动；`Delete` 删除；`Ctrl+D` 复制；双击进入编辑（用覆盖的 textarea，不用 prompt）。
- **算法**：`fillText` + 可选 `strokeText`；`textBaseline='top'`、锚点定位；多行按 `\n` 拆行，行高 1.2；导出按目标分辨率重新排版。
- **字体**：系统栈 `"Microsoft YaHei", "PingFang SC", "Noto Sans SC", sans-serif`，离线不加载网络字体；跨机器字体差异写进使用说明。
- **边界与失败**：空文本不渲染；超大字号（>图高）clamp；旋转文字命中测试用逆变换。
- **验收**：预览与 1500px 导出位置误差 ≤2px；中文无豆腐块。

### 8.7 F7 对象抠图

- **交互**：一键执行；进度条；完成后可换底色（透明/白/黑/自定义）、边缘羽化滑杆、去污开关；支持擦除/恢复笔刷微调（P1）。
- **算法**：letterbox 到 1024² → 推理得 alpha → 双线性放大回原图 → 羽化 1–2px + 对比度拉伸 → 合成 RGBA → 去污（反预乘减背景色）→ 生成新底图版本。
- **模型分级**：u2netp（4.5MB，极速）/ IS-Net int8（45MB，默认）/ RMBG-1.4（44MB，个人可选，非商用）/ BiRefNet-tiny（实验，WebGPU only）。
- **边界与失败**：纯色图/无主体图提示"未检测到明显主体"；推理超时 60s 可取消；模型加载失败给重试按钮。
- **验收**：12MP 人像 ≤8s；透明 PNG 在深浅两色底上无明显白边。

### 8.8 F8 对象移除

- **交互**：E 键进入涂抹模式（红色半透明遮罩）→ 执行按钮 → 进度 + 取消 → 结果前后对比滑杆。
- **算法**：mask 包围盒外扩 64px（或短边 20%）→ 裁 ROI 补方形 → 缩放 512² → 张量 `image[1,3,512,512]∈[0,1]`、`mask[1,1,512,512]`（1=洞）→ 推理 → 输出 0–255 RGB → 缩回 ROI → 羽化 mask（4–8px）合成 → 局部颜色匹配 → 新底图版本。
- **模型策略**：mask 面积占比 <15% 自动用 MI-GAN（快）；否则提示建议 LaMa（慢、结构更好）。**LaMa 强制 WASM**，120s watchdog，超时终止 Worker 并回退 MI-GAN。
- **边界与失败**：对象 >40% 画面提示分块处理；推理不可中断，"取消"= terminate Worker + 用缓存字节重建 session。
- **验收**：512 区域 MI-GAN ≤2s、LaMa ≤10s（i5-7500）；取消后 2s 内恢复可交互。

### 8.9 F9/F10 尺寸与导出

- **交互**：预设（原始/1500×1500/1080×1080/1920×1080/1080×1920/自定义）+ 锁比例 + contain（留白）/cover（裁满）二选一；格式 JPG/PNG/WebP；质量滑杆；"导出 ≤10MB"开关。
- **算法**：裁剪+缩放合并为一次 `drawImage(srcRect → dstRect)`，`imageSmoothingQuality='high'`；缩小 >2× 分两步降采样；放大 >2× 加轻锐化；JPG 先铺底色（默认白）；体积超限时二分质量（2–4 次）。
- **元数据**：canvas 重编码天然丢 EXIF/GPS，视为隐私优点；v1 不做 EXIF 回写。
- **命名**：`原名_编辑_1500x1500.jpg`，绝不覆盖原图。
- **验收**：1500×1500 JPG 导出 ≤3s；"≤10MB"开关下输出必达标或给出明确降级建议。

## 12. 打包、分发与升级

- **开发期**：绿色文件夹 + `启动.bat` + `server.exe`（约 8MB 的静态服务，或内置便携 Python）。目录：

```
图片编辑器/
├─ app/            # index.html + js + css + ort/ + models/
├─ server.exe（或 server.py）
├─ 启动.bat
└─ 使用说明.txt
```

- **正式交付**：套 Electron 壳出单 EXE（自带 Chromium，行为最可控，包体约 450–500MB）；Tauri 更小但依赖 WebView2，备选。
- **升级策略**：`app/` 与 `models/` 分离，升级只换 app；模型清单带版本号。
- **安全头**（服务端统一加）：

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval';
  img-src 'self' blob: data:; connect-src 'self' blob:; worker-src 'self' blob:;
  style-src 'self' 'unsafe-inline'; font-src 'self'
```

- **防呆**：关闭页面前 `beforeunload` 提示；编辑状态（不含位图）自动写 IndexedDB，重开可恢复。
